## 004: 外部変更の取り込みで Editor を差し替えない / モデルは URI から引く (§10)

- date: 2026-08-22
- context: ファイルパネルに「ウィンドウ/タブがアクティブになったらディスクと突き合わせて
  再読み込みする」機能を追加した。ユーザー仕様は「画面は Loading」だったが、既存の
  `common.loading` プレースホルダー(`EditorGroupPane.tsx` の renderBody で `<Editor>` と
  排他)を流用すると Monaco がアンマウントされる経路になることが設計時に判明した。
  あわせて、応答を反映するとき `editor.getModel()` の URI 一致をガードにすると、
  タブから離れている間に応答が返った場合にモデルだけ取り残される穴が見つかった。
- change: §10 を追加。(a) 進行中表示は差し替えでなくオーバーレイ、150ms 遅延で明滅を
  避ける。(b) 反映先モデルは `monaco.editor.getModel(Uri)` で引き、URI 一致は viewState の
  保存/復元にだけ使う。既存の `reloadWithEncoding` は同一グループのアクティブタブ限定の
  ユーザー操作なので現状のままとし、**触っていない箇所は書き換えない**。
  代替案「Loading 中は入力を止める(オーバーレイで pointer-events を塞ぐ)」は退けた —
  入力があれば判定が apply から conflict へ倒れて編集が保護されるため、止める必要がない。
- supersedes: —
- result: 隔離実機で、スクロール位置は先頭行 23 → 23 のまま保持、700ms のレイテンシー注入
  時のみオーバーレイが出て通常は出ないこと、入力直後にチェックを撃っても入力が失われず
  新規コンソールエラーが 0 であることを確認(実機 54 チェック green)。

## 005: 初期値プロップに state を流し戻さない (§11)

- date: 2026-08-29
- context: 「パネルのリサイズハンドルが稀にドラッグと逆方向に動く。再現方法は不明。
  DnD で位置を変えると治ることもある」というユーザー不具合報告。typecheck・vitest 542 件は
  green で、コード読解だけでは順序ズレの成立条件に到達できなかった。隔離ブラウザーに
  react-resizable-panels だけを載せた使い捨てページを立て、対照条件込みの真理値表
  (表示中×部分再登録 / 非表示中×全再登録 / 非表示中×部分再登録 / 通常ドラッグ 40 連続) を
  実測して、**非表示中の部分再登録でだけ** +60px ドラッグが左 -58 / 右 +58 に反転することを
  特定した。
- change: §11 を追加。Why = ライブラリーが保持するパネル順は登録時の実測ジオメトリー由来で、
  `display:none` 下では全て 0 になり並べ替えが効かない。そこへ `defaultSize` に生の state を
  流し戻すと部分再登録が起き、Group 再マウントまで直らない順序ズレになる。
  How = 初期値プロップを `useRef(initial).current` で凍結する (`SplitPanel.tsx`)。
  代替案「ビューが再表示されたら Group を再マウントして順序を作り直す」は退けた —
  Monaco とターミナルの再マウントコストを払ううえ、原因ではなく結果を毎回打ち消す形になる。
  未解明点として「アプリ内で非表示中にサイズが変わる経路」が特定できていないことを
  §11 に明記した (機構と修正は実測済みだが、断定はしない)。
- supersedes: —
- result: 同一手順の対照で、修正前 [-58, 0, +58] → 修正後 [+60, -60, 0]。隔離実アプリでも
  上下/左右ドラッグの方向、分割・クローズ後の方向、リロード後のサイズ復元 (653:174) を確認。
